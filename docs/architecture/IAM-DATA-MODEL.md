## Conventions

- **Namespace:** one PostgreSQL schema per context; IAM's is `iam`. Only IAM's infrastructure layer reads or writes it. This exercises ADR-005's provisional namespace mechanism as schema-per-context.
- **Tenant scoping:** every tenant-owned row carries `org_id`, and lookups always include it.
- **No cross-context foreign keys:** `repo_id` is REPO's opaque ID. Foreign keys exist only between IAM tables.
- **Secrets:** session IDs and CI upload tokens are stored only as SHA-256 hashes (32 bytes). Raw values are never stored or logged.
- **IDs:** `uuid` generated by the application (uuid4). No database defaults.
- **Times:** `timestamptz`, UTC.
- **Constraint names:** follow the migrations naming convention (`pk_<table>`, `fk_<table>_<column>_<referred table>`, `uq_<table>_<column>`, `ck_<table>_<name>`, `ix_<column label>`).

## Tables

### `iam.orgs` (tenant root)

| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | Primary key |
| `name` | text | Not null |
| `created_at` | timestamptz | Not null |

Org suspension is added with the suspension use case.

### `iam.users` (human principals)

Not in the original review list, but memberships and sessions need a principal to point at, and sign-in must map a verified external subject to one stable user (PRODUCT-SCOPE §3.1).

| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | Primary key |
| `idp_issuer` | text | Not null; the sign-in issuer (the GitHub App) |
| `idp_subject` | text | Not null; the GitHub user ID |
| `github_login` | text | Not null; for display only, refreshed at each sign-in |
| `created_at` | timestamptz | Not null |
| | | Unique (`idp_issuer`, `idp_subject`) |

`github_login` is personal data and falls under the retention policy. The GitHub user ID from sign-in is also the identity REPO uses for live code-host permission checks (ADR-009: the same GitHub App), so no separate identity-link table is needed.

### `iam.memberships`

| Column | Type | Constraints |
|---|---|---|
| `org_id` | uuid | Foreign key → `orgs.id` |
| `user_id` | uuid | Foreign key → `users.id` |
| `org_admin` | boolean | Not null, default false |
| `created_at` | timestamptz | Not null |
| | | Primary key (`org_id`, `user_id`); index on `user_id` (a user's orgs at sign-in) |

`org_admin` maps to `OrgAccess.org_admin`: it implies `repo.configure` on every org repo but never `repo.approve` (PRODUCT-SCOPE §3.3).

### `iam.repo_grants`

| Column | Type | Constraints |
|---|---|---|
| `org_id` | uuid | Not null |
| `user_id` | uuid | Not null |
| `repo_id` | uuid | Not null; REPO's ID, no foreign key |
| `grant` | text | Check: one of `repo.view`, `repo.investigate`, `repo.approve`, `repo.configure` (the `Grant` values) |
| `granted_by` | uuid | Not null; the granting user (no foreign key, so removing the granter keeps history) |
| `created_at` | timestamptz | Not null |
| | | Primary key (`org_id`, `user_id`, `repo_id`, `grant`): grant and revoke are idempotent |
| | | Foreign key (`org_id`, `user_id`) → `memberships` on delete cascade: a grant can only name a member of **the same org** |
| | | Index on (`org_id`, `repo_id`) (who can access a repo) |

Rows hold explicit grants only; implications and the org-admin rule are applied in `effective_grants()`. Revoking deletes the row; the history lives in the audit log. Who may grant, and the grantee's matching code-host access, are checked before insert (`may_grant()`, ADR-011 I).

### `iam.sessions` (per user, not tenant-owned)

| Column | Type | Constraints |
|---|---|---|
| `id_hash` | bytea | Primary key; check length = 32 |
| `user_id` | uuid | Foreign key → `users.id` on delete cascade |
| `created_at` | timestamptz | Not null |
| `last_seen_at` | timestamptz | Not null |
| `expires_at` | timestamptz | Not null; `created_at` + 12 h (ADR-011 B, provisional) |
| `revoked_at` | timestamptz | Null until revoked |
| `revoke_reason` | text | Check: one of `rotated`, `signed_out`, `revoked_by_admin`, `privilege_change` |
| | | Check: `revoked_at` and `revoke_reason` are both null or both set |
| | | Index on `user_id` (revoke all of a user's sessions); index on `expires_at` (cleanup) |

- `last_seen_at` is updated only when it is older than 5 minutes (provisional), so most requests do not write.
- Rotation on sign-in inserts a new row and revokes the old one with `rotated` in the same transaction. A privilege change revokes the user's sessions with `privilege_change`.
- The org a request acts in is not stored on the session; it comes from the request and is checked against `memberships`.

### `iam.ci_upload_tokens`

| Column | Type | Constraints |
|---|---|---|
| `id` | uuid | Primary key |
| `org_id` | uuid | Foreign key → `orgs.id` |
| `repo_id` | uuid | Not null; REPO's ID, no foreign key |
| `token_hash` | bytea | Unique; check length = 32 (SHA-256 of the full token string as sent, `fpi_…`) |
| `display_prefix` | text | Not null; the first 8 characters after `fpi_`; check length = 8 |
| `created_by` | uuid | Not null |
| `created_at` | timestamptz | Not null |
| `revoked_at` | timestamptz | Null until revoked |
| | | Index on (`org_id`, `repo_id`) |

## Queries it must support

| Query | Shape |
|---|---|
| Session lookup | `sessions` by `id_hash` where `revoked_at` is null, `expires_at > now()`, and `last_seen_at > now() - 2 h`; then update `last_seen_at` if older than 5 minutes |
| Build `OrgAccess` | `memberships` by (`org_id`, `user_id`) plus `repo_grants` by (`org_id`, `user_id`); a missing membership denies |
| Grants on one repo | `repo_grants` by (`org_id`, `repo_id`) |
| Org member count (D2) | count of `memberships` by `org_id` |
| Last-admin guard | count of admins by `org_id`, taken under a row lock on the `orgs` row in the same transaction as the change |
| CI upload token lookup | `ci_upload_tokens` by `token_hash` where `revoked_at` is null, giving (`org_id`, `repo_id`) |
| Revoke a user's sessions | update `sessions` by `user_id`, setting `revoked_at` and `revoke_reason` |

A grant row naming a repo of another org cannot widen access: authorization compares the access's org with the org REPO reports for the repo (`decide()`), so the mismatch is denied.

## Cleanup (provisional)

A background job (ADR-006) deletes sessions 30 days after they expire or are revoked, and deletes revoked CI upload tokens 1 year after revocation. Both periods are calibrated later.

## Out of scope

Each arrives with its own use case: org suspension, the platform operator role, break-glass grants, quotas, and the org retention-policy settings.
